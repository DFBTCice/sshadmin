USER GUIDE

SSHAdmin User Guide

Manage connections, work in terminals, keep remote tasks running and connect your local AI.

macOSChinese / English13 chaptersComplete command reference

For SSHAdmin for macOS 0.2.0, CLI schema 1. Examples use the host alias dev-server and tmux session work; replace them with your own values. Do not type the angle brackets around placeholders such as <alias>.

Start with the quick start, then use the relevant chapter when you need details. The installed program's --help describes its actual command contract.

1. Quick start

1.1 Connect using an alias

Run these commands in macOS Terminal, another terminal, or your local AI's terminal:

sshadmin ssh dev-server

Commands you enter after login run on the server. Type exit to leave. To run a short check and return to your Mac:

sshadmin ssh dev-server 'hostname; id -un'

The remote command's exit code is returned; success is normally 0.

1.2 Find existing hosts

Open Hosts. SSHAdmin reads concrete aliases from ~/.ssh/config and its Include files. You can also run:

sshadmin list

1.3 Add a password host

  1. Choose Hosts → Add and enter an alias, address, username and port.
  2. Select password authentication and enter the password, or save it later in host details.
  3. Choose Preview changes, inspect the diff, and apply it.
  4. Run Test and trust. Compare the fingerprint with a trusted source before accepting it. Complete any macOS Keychain authorization yourself.
  5. Allow AI credential use for this host and verify a fresh, non-interactive connection.
  6. Use sshadmin ssh <alias> without repeatedly entering the saved password.

1.4 Keep a task running after closing the app

Open tmux, select the host, enable management, enter a session name, then choose Create and attach. Start the task inside that session. Close its terminal tab or press Ctrl+B, release, then D to detach. Later, select the same host and session and choose Attach.

End terminates a remote session; it is not a detach button. The remote server, tmux and the task must remain running.

2. Understand the main concepts

2.2 Choose the right connection entry point

Entry pointTypical useSaved credentials
ssh dev-serverOrdinary system SSHDoes not read SSHAdmin's saved passwords
sshadmin ssh dev-serverDaily work, AI terminals, pipes, forwarding and long tasksSubmitted when authorized and bound to the destination
sshadmin exec dev-server -c 'command' --jsonOne command with a structured resultUsed when its requirements are met

The CLI runs independently of the GUI and ultimately uses /usr/bin/ssh. Automatic password submission does not convert a server to public-key authentication. SSHAdmin does not install public keys or change the remote SSH service.

2.3 Alias, display name and address

The alias is the exact, case-sensitive Host name used in commands. The display name is a friendly UI label. The address is the real HostName, an IP or domain. Use sshadmin list to find the alias rather than guessing from a display name.

3. Manage hosts

3.1 Discover existing configuration

On first launch, SSHAdmin reads configuration without connecting or rewriting it. This defines the alias dev-server:

Host dev-server
    HostName 10.0.1.21
    User deploy
    Port 22

A previous ssh user@IP command, a known_hosts entry, or a private key file alone does not define a managed alias. Wildcards such as Host * supply inherited options, not a list of all servers. With dynamic Match rules, the UI shows statically available information; OpenSSH resolves the effective configuration at connection time.

External configuration edits trigger a refresh. Re-enter the page or restart if needed and inspect parser warnings.

3.2 Add a host

New managed blocks go into ~/.ssh/sshadmin.conf; SSHAdmin adds an Include in the main configuration when needed. Every app-managed write has a preview and automatic backup.

3.3 Edit and rename

Select a host, choose Edit, preview and apply. Existing hosts are edited in their original source file. A shared block can affect several aliases; use the option to edit only the selected alias when appropriate.

Use Rename to change the command alias, and Edit for the display name. Update your commands and AI instructions after renaming. If a source file changes externally, reload and generate a fresh preview. Destination or credential changes usually require Test and trust again.

3.4 Delete

Select Delete, inspect the diff, then confirm. This removes local connection configuration, not a remote server or its files. The dialog controls whether its Keychain credential is also removed. Credentials still referenced by other hosts are retained.

3.5 Search and organize

Search aliases, addresses, users and tags; filter by group, tags or recent use. Select a host for details or double-click to open its terminal. Language changes do not alter your aliases, notes, groups, tags or SSH configuration.

4. Passwords, private keys and credentials

4.1 Save or update a password

In host details, choose Save password…, select login password, save to Keychain, then Test and trust. Saved passwords are not displayed again. Update the entry after a server password change and verify it. Saving here does not change the remote account password.

4.2 Use a private key

Edit the host, select private key authentication, choose the existing file path, preview and apply. SSHAdmin stores the path without copying or exporting the key; moving the file can break login. System SSH reads the original file when authenticating.

For an encrypted private key, save a key passphrase with the corresponding key path. A key passphrase unlocks that key; it is different from a server login password.

4.3 Use an SSH Agent

Choose SSH Agent authentication and ensure that the app or AI process can access your agent. ssh-add -l lists agent key fingerprints. An unavailable agent, an unloaded key or hardware confirmation still requires your action.

4.4 Verification and AI readiness

Test and trust makes a real connection and asks you to verify an unknown fingerprint. AI ready records a successful fresh, non-interactive connection with strict host checking. It is not continuous monitoring; later network or credential changes may cause failure.

4.5 Update, unlink or delete

OperationEffect
UpdateReplaces a saved password/passphrase and requires verification
UnlinkStops this host using the entry; the Keychain item remains
DeleteRemoves the Keychain item, but refuses while another host references it

The Credentials page shows type, linked hosts, item status and update time. It cannot display or export password plaintext. Unlink a credential before deleting an unused entry. Metadata for a host whose configuration disappeared can remain orphaned and may be relinked when the alias returns.

4.6 AI authorization and jump hosts

The per-host AI switch controls future saved-credential use by SSHAdmin's automation entry points. Disabling it does not terminate existing connections, revoke keys, or prevent ordinary system SSH.

A jump host and a destination involve separate authentication. A destination's saved password is not submitted to a jump host challenge. Prepare jump-host authentication yourself or use an interactive terminal for OTPs and hardware confirmation.

5. Terminals, shortcuts and history

5.1 Open and switch panes

Hosts → Open terminal creates SSH. + in the tab bar opens a local terminal; its adjacent menu selects a host. Pane controls split horizontally or vertically, and each pane title is a target menu. Changing a pane's target replaces that pane's connection after confirmation when needed; other panes continue.

Check the pane title before operating. Use hostname and id -un if you are unsure whether you are on the Mac or the server. Switching the application language updates labels without replacing active terminal sessions.

Multiline paste asks for confirmation by default because newlines can execute commands.

5.3 Disconnect and restart

Closing a normal SSH pane disconnects it. A foreground task may end; independently detached processes may survive. Do not infer a task's state from the disconnection alone.

Restart restores tabs, split layout and connection targets, without reconnecting or replaying commands. Choose Connect to start a new connection.

5.4 Optional history

Settings → Terminal history → Save terminal history is off by default. It saves read-only screen content from normal terminals, not running processes, shell command history, tmux panes or alternate screens such as vim.

The default is 2,000 lines per pane, configurable from 200 to 10,000, with a 1 MiB per-pane and 32 MiB total cap. History stays locally, unencrypted, and may contain echoed commands or sensitive program output. Turning history off deletes saved history. Closing a pane/tab removes its history. Clearing does not stop programs; with saving enabled, later output is saved again. The most recent roughly 2–10 seconds may be lost after an abnormal exit.

6. Keep remote tasks in tmux

6.1 Requirements

Install tmux on the remote server; installing it only on your Mac is insufficient. SSHAdmin does not install it. Check without changing the server:

sshadmin ssh dev-server 'command -v tmux; tmux -V'

6.2 Manage sessions in the app

Select the host on the tmux page, enable management, then create and attach a session before starting a task. An inactive tmux server can simply mean that no sessions exist. The list shows names, IDs, windows, attached clients and creation time. After a successful query it refreshes about every five seconds while the page is visible and the window focused; refresh manually after errors.

Zero attached clients usually means nobody is viewing the session. Rename preserves the task. Names allow 1–64 ASCII letters, digits, underscores or hyphens, without spaces, dots or colons.

6.3 What survives closing the app?

EventResult
App/tab closed, Mac offline or shut downReattach if the remote tmux and task keep running
Ordinary SSH task outside tmuxNo persistence guarantee; it cannot be recovered through tmux
End session, or exit its last shellSession and its processes may end
Server restarts, tmux is killed or task exitsNo process restoration
Remote WSL shuts down or its Windows host restartsIts tmux process does not survive

Enabling management does not move a task already running outside tmux into it.

6.4 Use tmux from your own terminal

sshadmin ssh dev-server 'tmux list-sessions'
sshadmin ssh -t dev-server 'tmux new-session -s work'
sshadmin connect dev-server --tmux work
sshadmin connect dev-server --tmux '$3'
sshadmin ssh -t dev-server 'tmux attach-session -r -t =work'

The last command attaches a read-only client. Single quotes keep the local shell from expanding $3. These run remote tmux; there is no sshadmin tmux subcommand.

6.5 tmux keys

With its default configuration, press Ctrl+B, release, then D to detach, C for a window, N/P for next/previous, [ for copy mode (usually Q to leave), or ? for help. These differ from SSHAdmin's Command shortcuts. See the official tmux guide.

7. Complete SSHAdmin command reference

7.1 Install the command and set PATH

Choose AI integration → Install sshadmin command, or run:

/Applications/SSHAdmin.app/Contents/MacOS/sshadmin install-cli
command -v sshadmin
sshadmin --version

Installation creates ~/.local/bin/sshadmin without editing shell configuration. If needed, add the directory to your current terminal:

export PATH="$HOME/.local/bin:$PATH"

For persistence, add it once to your own appropriate shell configuration, commonly ~/.zshrc or ~/.zprofile, and reopen the terminal. An AI tool may use a different environment. The absolute application path works without PATH.

There are no add, remove, tmux, backup or credential get subcommands. Use the corresponding GUI pages. Commands that require a managed host take an exact alias. The pass-through ssh launcher can also hand unmanaged destinations to system SSH, without acquiring a saved password for them.

Put --lang system, --lang zh-CN or --lang en before the subcommand for a one-off message language:

sshadmin --lang en list --json
sshadmin --lang zh-CN doctor dev-server
sshadmin --lang en ssh dev-server 'hostname'

Otherwise messages follow the saved app preference and system language. JSON keys, error codes, user data and remote output keep the same contract. Arguments after ssh belong to OpenSSH, so a remote --lang argument passes through.

7.3 list

sshadmin list
sshadmin list --json

Reads local configuration without connecting. ai_ready records successful unattended verification; false may mean not yet verified rather than offline.

7.4 show

sshadmin show dev-server
sshadmin show dev-server --json

Shows connection, source, authentication and verification details without passwords. Addresses and usernames remain connection information; this is not the anonymous diagnostics export.

7.5 doctor

sshadmin doctor dev-server
sshadmin doctor dev-server --connect
sshadmin doctor dev-server --connect --json

Only --connect makes a real connection and records the result. It cannot approve an unknown fingerprint or solve an OTP for you; use Test and trust or an interactive entry point.

7.6 ssh

sshadmin ssh dev-server
sshadmin ssh dev-server 'hostname; id -un; df -h'
sshadmin ssh -t dev-server top
sshadmin ssh -o ConnectTimeout=10 -o ServerAliveInterval=30 -o ServerAliveCountMax=3 dev-server
sshadmin ssh -v dev-server 'hostname'

OpenSSH supplies -t (PTY), -T (no PTY), -v (diagnostics), and -o options. ConnectTimeout limits connection establishment, not the remote task's full runtime. SSHAdmin adds no execution or output limit to this launcher; the network, server and calling tool can impose their own limits.

Changing the destination with -p, -l, -J or related options can trigger CREDENTIAL_BINDING_CHANGED. Make intended changes in the app and verify again. Single-quote remote commands when remote variable expansion is intended: in 'echo "$HOME"', the remote shell expands $HOME. Do not concatenate untrusted input into shell commands. See OpenSSH documentation.

7.7 exec

sshadmin exec dev-server --command 'df -h'
sshadmin exec dev-server -c 'hostname; id -un' --json
sshadmin exec dev-server -c 'uname -a' --timeout 30 --json
printf 'hello\n' | sshadmin exec dev-server -c 'wc -c' --stdin --json

The command is one required string argument. Timeout defaults to 60 seconds; 0 removes the local execution timeout. Stdin forwarding is off unless --stdin is set. --json returns one JSON object rather than live stdout.

There is no interactive PTY. Use ssh -t or the GUI for vim, top or interactive sudo. Combined stdout/stderr processing is capped at 8 MiB, even with timeout zero. Use the launcher for continuous output or large streams.

Timeout, cancellation, output limits and network loss do not roll back remote operations. Inspect actual remote state before retrying.

7.9 connect

sshadmin connect dev-server
sshadmin connect dev-server --tmux work
sshadmin connect dev-server --tmux '$3'

Runs in the current interactive terminal. --tmux attaches an existing session; it does not create one. Arbitrary SSH options and --json are not accepted here.

7.10 trust

sshadmin trust dev-server
sshadmin trust dev-server --json

Requires an interactive terminal for human fingerprint confirmation when needed, then tests interactive and unattended connections. --json does not remove the human trust step. AI must not blindly accept new fingerprints.

7.11 credential

sshadmin credential set dev-server
sshadmin credential set dev-server --kind password
sshadmin credential set dev-server --kind passphrase --identity "$HOME/.ssh/id_ed25519"
sshadmin trust dev-server
sshadmin credential unlink dev-server
sshadmin credential delete dev-server

Saving reads a hidden value twice from a real terminal. There is no password argument, piped password input or credential --json mode. Unlink retains the Keychain item. Delete first unlinks this host, then tries to delete the item; references from other hosts keep it. Read the message or Credentials page rather than inferring complete deletion from exit 0. Delete unlinked orphan entries from the Credentials page.

7.12 install-cli and uninstall-cli

/Applications/SSHAdmin.app/Contents/MacOS/sshadmin install-cli --json
/Applications/SSHAdmin.app/Contents/MacOS/sshadmin install-cli --dir "$HOME/bin" --json
/Applications/SSHAdmin.app/Contents/MacOS/sshadmin uninstall-cli

Use the same custom directory when uninstalling. Installation will not overwrite another program's link/file; removal only affects a link pointing to this application. Removing the link does not remove the app, configuration, credentials or remote data.

8. Connect your local AI

8.1 Preparation

Configure the host, save any password/passphrase, verify its fingerprint through Test and trust, complete Keychain authorization, then enable per-host AI credential use. Install the command from AI integration and copy that page's instructions to an AI capable of executing local terminal commands.

No global AI settings are modified automatically. This is not an MCP server. A cloud AI cannot automatically read this Mac's local configuration or Keychain. The GUI need not stay open for CLI use.

8.2 Instructions you can share

SSHAdmin is installed locally. Use sshadmin, or its absolute path:
/Applications/SSHAdmin.app/Contents/MacOS/sshadmin
First run list --json to confirm the exact managed alias.
Use sshadmin ssh <alias> '<authorized command>' for interactive work,
live output, pipes or long tasks. Use exec --json for structured results.
Never request, read or export saved passwords or put them in arguments,
scripts or logs. Do not change the destination, user, port, jump host or
trust records. Stop and explain Keychain, fingerprint, OTP or credential
errors. After timeout or disconnection, inspect remote state before
replaying a command. For tasks that must outlive the client, start inside
remote tmux. Stay within the user's authorization; ask before new
destructive operations.

For example: “Use SSHAdmin to connect to dev-server and only check hostname and disk usage.” No password needs to be pasted into chat.

8.3 Common questions

The AI uses its own execution terminal, not the GUI terminal. SSH login and remote sudo are separate authentication steps; a saved SSH password does not automatically answer sudo or arbitrary application prompts. Calling tools may impose their own sandbox, approval, runtime or output restrictions.

9. Common recipes

9.1 Read-only server checks

sshadmin ssh dev-server 'hostname; id -un; uname -sr; uptime; df -h'

These run remotely and assume common Linux tools are available.

9.2 Follow logs

sshadmin ssh dev-server 'tail -f /path/to/app.log'

Use an authorized real log path. Press Ctrl+C to stop. Continuous output suits the launcher rather than bounded exec.

9.3 Forward a local-only web service

sshadmin ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:8080:127.0.0.1:3000 dev-server

Keep it running and visit http://127.0.0.1:8080 on your Mac. This binds only to Mac loopback and forwards to the server's local port 3000. Use another local port if 8080 is busy. The server must allow forwarding and its service must already run. Stop with Ctrl+C.

9.4 Run a long task

sshadmin ssh -t dev-server 'tmux new-session -s work'

Start your task inside. Detach with Ctrl+B, then D. Return using sshadmin connect dev-server --tmux work. tmux preserves a running environment, not necessarily a complete durable task log; configure task logging separately when needed.

9.5 File transfer

There is no built-in SFTP browser. Tools needing a remote shell can use the launcher, for example this rsync dry run (rsync must exist on both machines):

rsync -avn -e 'sshadmin ssh' ./local-dir/ dev-server:/path/to/remote-dir/

-n previews without transfer. Actual transfer writes the destination, so verify paths first. scp -S and sftp -S need a single executable path, not sshadmin ssh plus a subcommand. Ordinary key-based scp/sftp remain available but do not automatically retrieve SSHAdmin's saved passwords.

10.2 Backup and restore

App-managed configuration changes keep the latest 20 backups. In Settings, choose a backup, Preview restore, inspect the diff and restore. This changes local SSH configuration. It is not a full backup of Keychain, private files, running processes or history. External manual edits do not necessarily create SSHAdmin backups.

Edit configuration text… supports complex SSH directives with validation, diff preview and backup. Prefer the host form unless you understand SSH configuration syntax.

11.3 macOS Local Network permission

If ordinary Terminal connects but SSHAdmin does not, check System Settings → Privacy & Security → Local Network for SSHAdmin. If another terminal or AI app launches the connection, that application may need permission too. Authorizing SSHAdmin does not authorize every caller, and a real network failure may produce the same symptom.

11.4 AI fails while your terminal works

Compare PATH, Keychain authorization, SSH Agent environment, Local Network permission, and the AI tool's sandbox/approval rules. Identify whether an error came from SSHAdmin, OpenSSH or the calling tool. A command blocked before execution is not evidence of a server connection failure.

11.5 Login and remote privileges

SSH login permission differs from remote file access and sudo privileges. SSHAdmin does not elevate remote accounts or answer arbitrary password prompts after login.

12. Update, migrate and uninstall

12.1 System OpenSSH

About reports /usr/bin/ssh -V. SSHAdmin uses that fixed system path. A macOS update can update SSH; installing Homebrew SSH does not automatically switch the path. Configuration and Keychain items are stored separately, but compatibility with older servers should still be verified after updates.

12.2 Update the application

Replace the app at its original installation path, then check version, host list and a connection. A changed code-signing identity may require renewed Keychain authorization. Report build date and symptoms as well as the version when diagnosing locally repackaged builds.

12.3 Move to another Mac

There is no one-click migration or cloud sync. Account separately for SSH/Include files, original private keys, app metadata, Keychain migration/authorization and PATH. Changed paths need updating. Keep the old environment until you verify the new one; ordinary text backups are not a substitute for secure credential migration.

12.4 Remove only what you intend

GoalAction
Remove the short commanduninstall-cli; other data remains
Remove one connectionDelete it on Hosts
Remove a passwordUnlink and delete through Credentials or its CLI
Stop saving terminal screensDisable history in Settings
Remove the appDelete SSHAdmin.app; stored configuration and Keychain items are not automatically removed

Do not delete your entire ~/.ssh directory as an uninstall step; other tools may depend on it.

12.5 Current boundaries

SSHAdmin provides local host management, system SSH, password/key support, split terminals, remote tmux, a local AI CLI, backups and optional screen history. It does not currently provide multi-user permissions, cloud sync, a web admin console, an SFTP browser, broadcast commands, MCP, automatic remote software/public-key installation, or process recovery after server restart.

Apple Silicon is the verified package platform. Public builds are locally signed and not notarized; there are no current Intel, Windows or Linux application packages. The interface supports Chinese and English; shell programs and macOS-controlled dialogs use their own language rules.
